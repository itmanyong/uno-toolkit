## signals-transform 重渲染机制澄清（用户疑问）

- 用户疑问：`examples/signals-transform/src/App.tsx` 中新增的 `App2` 只渲染 `<>{count}</>`（信号对象，非 `.value`），预期 count 更新时 App2 不重渲染，但实际每次点击都重渲染，以为插件与官方 `@preact/signals-react-transform` 行为不同。
- 结论：uno 插件行为正确且与官方一致。转换规则（`auto` 模式，见 `native-rust/src/signals_transform/mod.rs` 的 `contains_signal_access`）只对**读取 `.value`** 的组件注入 `useSignals`；`App2` 未被注入、未订阅信号。
- 真正原因：父组件 `App` 读了 `count.value` 被注入 `useSignals(1)` → 订阅 count → 每次点击整组件重渲染，React 把未 `memo` 的子组件 App2 一起重跑（父重渲染向下冒泡）。官方插件同理，App2 也会因此重渲染。
- fine-grained 机制来源：`@preact/signals-react/runtime` 在加载时给 `Signal.prototype` 打补丁（`runtime/src/index.ts` `SignalValue`），把**直接渲染 Signal 对象**变成内部 `SignalValue` 组件，只更新该文本节点、宿主组件无需重跑——但前提是宿主没被父组件强行重渲染。
- 修复：把 `App2` 用 `React.memo` 包裹（已在 App.tsx 实施）。App 仍订阅重渲染，但 `<App2/>` 无 props 变化 → memo 跳过 App2 函数执行（app2Render 冻结），内部 `SignalValue` 仍实时更新计数。
- 经验：要让某组件"不重渲染但值实时刷新"，要么该组件被 `memo` 隔离父冒泡，要么连父组件也别读 `.value`（改用 `<>{signal}</>` 直接渲染）使其整体走 SignalValue 细粒度。
